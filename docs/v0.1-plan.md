# AgentLane v0.1 implementation plan

## Inspection findings

The existing standard-library CLI owns all behavior in `bin/board`; the stdio MCP wrapper
delegates to it. Each clone has a disposable board worktree under Git's common directory.
JSON task, claim and member files and per-member JSONL notes/events live on an orphan `board`
branch. Mutations fetch, replay and retry a fast-forward push. Work uses `claim/*` branches;
landing rebases, checks paths, runs Bash gates and retries competing main pushes. PR review,
TTL expiry, heartbeats, handoffs, hot paths, generated Markdown and optional Slack already exist.
The tests use local bare remotes; the simulator exercises contention and recovery. Seven agent
configurations share the MCP server. MIT and community contribution files are already present.

## Keep

- Git branches, JSON state, standard-library runtime, legacy commands and MCP tool names.
- Existing gates, direct landing, PR mode, notes, hot paths, expiry and simulation coverage.
- Repository-owned configuration and gates; no service, database or agent runtime.

## Gaps to close

- No installable CLI, version, doctor, task details or simple list filters.
- Partial-prefix globs can miss overlaps; state and identifiers lack validation.
- Expiry/render paths can ignore rejected pushes; same-checkout commands can race.
- Main landing and board completion are separate writes; a gate can outlive ownership.
- Missing gates silently pass; hooks can be overwritten; failed join leaves local identity.
- Slack timestamps can skip events from the same second and JSON narration mixes output.
- Documentation overstates automatic heartbeats and some safety guarantees.

## Ordered implementation

1. Package the existing implementation; retain `bin/board`, add the `agentlane` entry point,
   version, command aliases, positional task arguments, `--paths`, list/show and read-only doctor.
2. Harden validation, ownership/expiry, local operation serialization and concurrent claims.
   Make direct main + board updates atomic with Git; preserve PR mode and explicit recovery.
3. Polish installation, gates, events/Slack, MCP and agent integrations. Add deterministic
   failure and contention tests as each behavior changes.
4. Rewrite onboarding and architecture docs, add a three-worker example, changelog and release
   instructions. Add packaging and lint checks to CI.
5. Run the complete suite, installed/wheel smoke checks and a local concurrent simulation;
   inspect the final diff and document remaining limits.

## Compatibility and boundaries

Existing task IDs and schema fields remain readable. New fields are additive. New task IDs may
use `AL-N` allocated inside the board transaction. Direct landing will require remote atomic-push
support; fail clearly rather than downgrade the guarantee. Claims remain cooperative ownership,
not an authorization boundary. PR review/merging remains a hosting workflow. Source maintenance
uses ordinary local commits; this task must not push, publish a release, or post externally.
